# توحيد مودلات الأذونات (المايك + الإشعارات)

**التاريخ:** 2026-06-02
**الحالة:** معتمد (بانتظار خطة التنفيذ)

## الخلفية والمشكلة

التطبيق فيه أكثر من مودل لطلب الأذونات، وكل واحد مختلف في الشكل والنبرة والسلوك:

| المودل | المكان | المكوّن الحالي | السلوك |
|--------|--------|----------------|--------|
| مايك — onboarding | `onboarding_screens.dart` `_showMicAccessDialog` | `CupertinoAlertDialog`/`AlertDialog` سادة | يطلب إذن النظام |
| مايك — المحادثة | `smart_companion_chat_screen.dart` `_showMicPermissionDialog` | `CupertinoAlertDialog`/`AlertDialog` سادة | يفتح إعدادات التطبيق |
| إشعارات — تفعيل | `profile_screen.dart` `_EnableNotificationsDialog` | `_ConfirmationDialog` مخصّص (أيقونة + أزرار ملوّنة) | يطلب إذن النظام |
| إشعارات — إيقاف | `profile_screen.dart` `_DisableNotificationsDialog` | `_ConfirmationDialog` مخصّص | يفتح الإعدادات |

مشاكل: نظامان بصريان مختلفان، نصوص غير متّسقة («تسمعك» مقابل «تتحدث» مقابل «تعبّر»)، تسمية غير موحّدة للمرافق («المرافق الذكي» مقابل «مرافقك»)، وسلوك غير موحّد.

نص iOS الرسمي في `Info.plist` (`NSMicrophoneUsageDescription`) أيضًا بصياغة مختلفة عن باقي المودلات.

## الهدف

مكوّن مودل أذونات **واحد بشكل النظام**، بسلوك آبل القياسي، ونصوص موحّدة، يُستخدم لكل أذونات المايك والإشعارات.

## القرارات المعتمدة

1. **الشكل:** نافذة بشكل النظام — `CupertinoAlertDialog` على iOS و`AlertDialog` على Android. بدون أيقونة مخصّصة ولا أزرار ملوّنة.
2. **اتجاه النص:** تلقائي حسب لغة المحتوى — عربي RTL (يمين)، إنجليزي LTR (يسار).
3. **السلوك (آبل القياسي):**
   - أول مرة (الإذن لم يُتخذ فيه قرار بعد): زر «السماح» يطلق نافذة إذن النظام الحقيقية مباشرة.
   - مرفوض نهائيًا (`isPermanentlyDenied`): الزر يصير «فتح الإعدادات» ويفتح إعدادات الجهاز.
   - سبب تقني: iOS لا يعرض الإذن في الإعدادات قبل أول طلب فعلي، فأول تفاعل لازم يكون نافذة النظام.
4. **المزامنة:** حالة التطبيق تعكس إذن النظام الحقيقي دائمًا. يُعاد قراءة الحالة عند الرجوع للتطبيق (`WidgetsBindingObserver` + `didChangeAppLifecycleState`).
5. **توقيت ظهور كل مودل:**
   - **المايك:** في الـonboarding (موجود) + شاشة المحادثة عند رفض الإذن (فتح الإعدادات).
   - **الإشعارات:** بعد **أول دخول للرئيسية** (`MainShell`)، مرة واحدة فقط.

## التصميم

### المكوّن الموحّد: `SystemPermissionDialog`

دالّة/ودجت مشتركة (ملف جديد، مثلاً `lib/widgets/dialogs/system_permission_dialog.dart`) تعرض نافذة بشكل النظام، تأخذ:

- `title` — عنوان
- `message` — نص الشرح
- `confirmLabel` / `cancelLabel` — تسميات الأزرار
- `textDirection` — يُحدَّد من لغة المحتوى (افتراضي RTL للعربي)
- ترجع نتيجة المستخدم (موافق / إلغاء)

تُغلّف بـ`Directionality` بالاتجاه المناسب. على iOS تستخدم `CupertinoAlertDialog`، وعلى Android `AlertDialog`.

### منطق الإذن المشترك

دالّة مساعدة موحّدة (مثلاً `PermissionFlow.request(...)`) تنفّذ سلوك آبل:

```
status = await permission.status
if status.isGranted: return granted
if status.isPermanentlyDenied:
    عرض المودل بزر «فتح الإعدادات» → openAppSettings()
else:
    عرض المودل التمهيدي بزر «السماح»
    إذا وافق: result = await permission.request()
    return result
```

### نقاط الدمج

| الملف | التغيير |
|-------|---------|
| `widgets/dialogs/system_permission_dialog.dart` | **جديد** — المكوّن الموحّد |
| منطق الإذن المشترك | **جديد** — دالّة `PermissionFlow` تطبّق سلوك آبل |
| `onboarding_screens.dart` | استبدال `_showMicAccessDialog` بالمكوّن الموحّد + إضافة `WidgetsBindingObserver` للمزامنة |
| `smart_companion_chat_screen.dart` | استبدال `_showMicPermissionDialog` بالمكوّن الموحّد + إضافة `WidgetsBindingObserver` |
| `profile_screen.dart` | استبدال `_EnableNotificationsDialog` و`_DisableNotificationsDialog` بالمكوّن الموحّد (يحتفظ `_ConfirmationDialog` لتأكيد تسجيل الخروج وغيره من غير الأذونات) |
| `main_shell.dart` | في `initState`: لو أول دخول للرئيسية والإذن قابل للطلب → عرض مودل الإشعارات. يُخزَّن علم `seenNotificationsPrompt` (نفس نمط التخزين الموجود في المشروع) لعرضه مرة واحدة |
| `Info.plist` / `AndroidManifest.xml` | توحيد نص `NSMicrophoneUsageDescription` مع النبرة الجديدة |

## النصوص المعتمدة

### مودل المايك
| الحالة | النص |
|--------|------|
| العنوان | «السماح بالوصول للميكروفون؟» |
| النص (أول مرة) | «اسمح بالوصول للميكروفون عشان تتكلم مع مرافقك الذكي بصوتك، وما نستخدمه إلا وقت المحادثة الصوتية.» |
| النص (مرفوض) | «فعّل الميكروفون من إعدادات جهازك عشان تتكلم مع مرافقك الذكي بصوتك.» |
| الأزرار (أول مرة) | «ليس الآن» / «السماح» |
| الأزرار (مرفوض) | «إلغاء» / «فتح الإعدادات» |

### مودل الإشعارات
| الحالة | النص |
|--------|------|
| العنوان | «تبي تذكيرات تساعدك تستمر؟» |
| النص (أول مرة) | «نرسل لك تنبيهات بسيطة تساعدك تستمر، وتقدر توقفها وقت ما تبي.» |
| النص (مرفوض) | «فعّل الإشعارات من إعدادات جهازك عشان توصلك تنبيهات تساعدك تستمر.» |
| الأزرار (أول مرة) | «لاحقًا» / «تفعيل الإشعارات» |
| الأزرار (مرفوض) | «إلغاء» / «فتح الإعدادات» |

### نص iOS الرسمي (`Info.plist`)
«تستخدم مِشْكَاة الميكروفون عشان تتكلم مع مرافقك الذكي بصوتك، وما يُستخدم إلا وقت المحادثة الصوتية.»

ملاحظات النبرة: سعودي دارج (عشان، تبي، وقت ما تبي)، توحيد «مرافقك الذكي» و«فتح الإعدادات».

## معايير القبول

- مودل واحد بشكل النظام يُستخدم لكل أذونات المايك والإشعارات.
- العربي يُحاذى يمين، الإنجليزي يسار.
- أول طلب للإذن يطلق نافذة النظام؛ بعد الرفض النهائي يفتح الإعدادات.
- حالة الإذن في التطبيق تتزامن عند الرجوع من الإعدادات (المايك + الإشعارات + التبديل في حسابي).
- مودل المايك يظهر في الـonboarding وفي المحادثة عند الحاجة.
- مودل الإشعارات يظهر مرة واحدة بعد أول دخول للرئيسية.
- النصوص مطابقة للجدول أعلاه.

## خارج النطاق

- لا تغيير على `_ConfirmationDialog` المخصّص لتأكيد تسجيل الخروج وباقي التأكيدات غير المتعلقة بالأذونات.
- لا تغيير على منطق إرسال الإشعارات نفسه (`push_service`).
